# Kiln Sharded Volume Format Specification (`volume.py`)

The sharded volume format stores 3D volumetric datasets as a multi-resolution Level of Detail (LOD) octree pyramid. Each level is divided into $64^3$ logical bricks padded with a 1-voxel halo on all sides ($66^3$ physical voxels) and packed into contiguous binary files (`lodN.bin`) using RFC-1952 Gzip streams with internal `Z_FULL_FLUSH` sync points for sub-brick random access.

---

## 1. Directory Structure

A converted volume directory contains the following files:

| File | Purpose |
| :--- | :--- |
| **`volume.json`** | Global volume metadata, dimensions, voxel spacing, LOD hierarchy, and auto-windowing parameters. |
| **`histogram.json`** | 1024-bin intensity histogram computed over the finest level (LOD 0). |
| **`lod{N}.bin`** | Concatenated Gzip-compressed $66^3$ physical bricks for level `N`. |
| **`lod{N}_index.json`** | JSON lookup table mapping `"bx/by/bz"` brick coordinates to byte offsets, sizes, and intensity statistics. |
| **`lod{N}_index.npy`** | Dense NumPy structured array `(nz, ny, nx)` with dtype `INDEX_DTYPE` (`offset`, `size`, `min`, `max`, `avg`) for fast Python slice indexing. |
| **`lod0_subindex.npy`** | Dense NumPy array `(nz, ny, nx, 65)` (`uint32`) storing relative byte offsets to each of the 64 sub-blocks inside every LOD 0 brick. |
| **`lod{N}_zindex.npy`** | *(LOD > 0 only)* Dense NumPy array `(nz, ny, nx, 67)` (`uint32`) storing relative byte offsets to each of the 66 XY Z-planes inside every LOD $> 0$ brick. |
| **`lod0_legacy66.bin` / `_index.json`** | *(Optional, generated on-demand)* Backward-compatible flat $66^3$ version of LOD 0 created by `ensure_legacy66_level_files`. |

---

## 2. Brick Geometry & Halo Padding

* **Logical Brick Size (`brickSize`):** $64 \times 64 \times 64$ voxels.
* **Physical Brick Size (`physicalSize`):** $66 \times 66 \times 66$ voxels ($64 + 2$), adding a 1-voxel border around the $64^3$ core.
* **Boundary Clamping:** At the outer boundaries of the volume (and where volume dimensions are not exact multiples of 64), the halo and any out-of-bounds voxels are edge-clamped (repeating the nearest valid boundary voxel).
* **Core Statistics:** Brick `min`, `max`, and `avg` statistics are computed strictly over the $64^3$ interior core (`brick[1:-1, 1:-1, 1:-1]`) as `float` values.
* **Downsampling:** Each subsequent LOD level (`lod + 1`) is generated by $2 \times 2 \times 2$ box-averaging of the current level with half-up rounding (`floor(mean + 0.5)`) and edge-clamping on odd dimensions, resulting in dimensions `((cd + 1) // 2, (ch + 1) // 2, (cw + 1) // 2)`.

## 3. Compression & Sub-Brick Layouts

Every brick in `lod{N}.bin` is a valid, standalone **RFC-1952 Gzip stream** consisting of:
1. A 10-byte Gzip header (`\x1f\x8b\x08\x00\x00\x00\x00\x00\x00\xff`).
2. Multiple raw DEFLATE blocks separated by `zlib.Z_FULL_FLUSH` sync markers (and terminated by `Z_FINISH` on the final block).
3. An 8-byte Gzip trailer (`<II`: CRC32 + ISIZE).

### Layout A: `tiled66` (LOD 0)
* **Goal:** Enable efficient sub-block streaming and memory-efficient localized decoding.
* **Partitioning:** The $66 \times 66 \times 66$ physical brick is split into **64 sub-blocks** corresponding to the spatial partitions:
  * $Z$ bounds: `((0, 17), (17, 33), (33, 49), (49, 66))`
  * $Y$ bounds: `((0, 17), (17, 33), (33, 49), (49, 66))`
  * $X$ bounds: `((0, 17), (17, 33), (33, 49), (49, 66))`
* **Sub-Index (`lod0_subindex.npy`):** Shape `(nz, ny, nx, 65)` of `uint32`. Sub-block `i` ($0 \le i < 64$) starts at `brick_offset + subidx[bz, by, bx, i]` and ends at `brick_offset + subidx[bz, by, bx, i + 1]`. Entry `64` marks the end of the DEFLATE body before the 8-byte Gzip trailer.

### Layout B: `z_sync` (LOD > 0)
* **Goal:** Fast random access to individual 2D XY planes at coarser LOD levels.
* **Partitioning:** The $66 \times 66 \times 66$ physical brick is packed as **66 consecutive $66 \times 66$ XY planes** (`z = 0 .. 65`), each flushed with `Z_FULL_FLUSH`.
* **Z-Index (`lod{N}_zindex.npy`):** Shape `(nz, ny, nx, 67)` of `uint32`. Plane `z` ($0 \le z < 66$) starts at `brick_offset + zidx[bz, by, bx, z]` and ends at `brick_offset + zidx[bz, by, bx, z + 1]`. Entry `66` marks the end of the DEFLATE body before the 8-byte Gzip trailer.

## 4. Metadata Schemas

### `volume.json`
```json
{
  "name": "sample_volume",
  "originalDimensions": [W, H, D],
  "voxelSpacing": [sx, sy, sz],
  "brickSize": 64,
  "physicalSize": 66,
  "maxLod": 3,
  "levels": [
    {
      "lod": 0,
      "dimensions": [W, H, D],
      "bricks": [nx, ny, nz],
      "brickCount": 512,
      "brickLayout": "tiled66",
      "binFile": "lod0.bin",
      "indexFile": "lod0_index.json"
    }
  ],
  "format": "uint8 | uint16",
  "packed": true,
  "compressed": true,
  "suggestedWindow": {
    "center": 127.5,
    "width": 255.0,
    "source": "auto"
  },
  "createdAt": "2026-11-06T12:00:00Z"
}
```
* **`originalDimensions` / `dimensions`:** Always stored in `[W, H, D]` (`[X, Y, Z]`) order, whereas in-memory NumPy/Dask arrays use `(D, H, W)` (`(Z, Y, X)`) order.
* **`suggestedWindow`:** Computed automatically during LOD 0 packing from the 0.5th and 99.5th percentiles of the middle Z slice (`mid_z = D // 2`).

### `lod{N}_index.json`
```json
{
  "lod": 0,
  "brickSize": 64,
  "physicalSize": 66,
  "brickLayout": "tiled66 | z_sync",
  "bricks": [nx, ny, nz],
  "totalBricks": 512,
  "totalBytes": 48291042,
  "compressed": true,
  "entries": {
    "0/0/0": {
      "offset": 0,
      "size": 94318,
      "min": 0.0,
      "max": 255.0,
      "avg": 42.18
    }
  }
}
```

### `histogram.json`
```json
{
  "version": 1,
  "dtype": "uint16",
  "min": 0,
  "max": 65535,
  "bins": 1024,
  "counts": [ ... 1024 integer bin counts ... ]
}
```
